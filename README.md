# Screen Translate

Самостоятельный Windows-проект в папке `game-translate`: перевод выбранного экранного текста **EN → RU**. WPF, Windows OCR, Яндекс / Google / Bing через GTranslate. Не требует Lazy Dictionary, его базы, браузерного расширения или WebView.

> **Статус: prerelease-кандидат 0.1.0.2, не проверенный игровой релиз.** Реальная регистрация, packaged OCR/сетевой self-test и сценарии второго запуска проверены; это не подтверждение игрового захвата или публикации релиза. В исходном проекте 22.10.2026 сообщалось о зависании Windows во время игры; причина не установлена. Программная отрисовка WPF и ограничения захвата уже присутствовали до выделения. Unit-тесты и сборка не подтверждают устранение зависания. Смешанный DPI, HDR и длительная работа поверх игры требуют ручной проверки.

## Требования

- Windows 11 24H2+ x64 (build 26100).
- Для сборки: .NET SDK **10.0.400** или совместимый patch согласно `global.json`.
- Для OCR: компонент English OCR в параметрах языка Windows и запуск приложения с package identity.
- Для локальной регистрации пакета: включённый пользователем Windows Developer Mode. Скрипт не меняет настройки безопасности.
- Интернет для перевода. Неофициальные интерфейсы GTranslate могут меняться, ограничиваться или быть недоступны.

## Сборка и тесты

Команды выполняются из корня проекта в PowerShell. Для текущего этапа официальный .NET SDK **10.0.400 x64** размещён в локальной `.tools/dotnet`, опубликованная SHA-512 проверена; системный PATH и `global.json` не менялись. SDK не входит в исходники: в другом окружении установите его отдельно или подготовьте собственную `.tools/dotnet`.

Release-тесты (зависимости уже восстановлены):

```powershell
.\.tools\dotnet\dotnet.exe test ScreenTranslate.slnx -c Release --no-restore
```

Безопасные script regression tests без дополнительных test frameworks:

```powershell
powershell.exe -NoProfile -File tests/scripts/Prepare-ScreenTranslate.Tests.ps1
```

Script tests используют fake publish/process/package/launch, временные файлы и локальную генерацию иконок. Они не запускают приложение или dotnet и не обращаются к установленному пакету.

Только подготовка автономной x64-сборки и development-layout, **без регистрации, запуска и завершения процессов**:

```powershell
powershell.exe -NoProfile -File scripts/Prepare-ScreenTranslate.ps1 -BuildOnly -DotnetPath ./.tools/dotnet/dotnet.exe
```

Результат каждого вызова — новый `artifacts/screen-translate-builds/<manifest-version>-<GUID>/`; точный путь выводится скриптом. Publish выполняется в уникальный staging, затем проверяются manifest, executable/runtime, assets и лицензия GTranslate. Только полный результат переносится в конечный каталог. Последующие запуски не меняют этот layout, даже при той же manifest-version; при ошибке удаляется только staging текущей попытки. Старый `artifacts/screen-translate/` и предыдущие builds не перезаписываются и не очищаются. Отдельный .NET runtime готовой сборке не нужен.

`-BuildOnly` разрешён при работающей старой установке и не требует Developer Mode: этот путь не вызывает process/package/Developer Mode checks, registration или launch. Без `-DotnetPath` скрипт ищет SDK в `.tools/dotnet/dotnet.exe`, затем в PATH.

## Установка

Для готового self-contained x64 ZIP: [инструкция Windows](docs/INSTALL-WINDOWS.md). Отдельные .NET SDK/runtime ему не нужны. Версия пакета — **0.1.0.2**, планируемый тег — `v0.1.0.2-preview.1`; [заметки prerelease](docs/RELEASE-0.1.0.2-preview.1.md) не являются подтверждением публикации.

Ниже — регистрация **из исходников**. Это отдельная операция, не часть безопасного build-only. Для регистрации закройте Screen Translate самостоятельно через трей и включите Developer Mode. При переносе существующей установки в новый layout **версия в исходном `Package.appxmanifest` должна быть строго выше установленной**. Каждый вызов создаёт новый путь, поэтому повторная регистрация той же версии будет отклонена. Скрипт не повышает версию автоматически, не делает downgrade, не удаляет пакет и не завершает приложение.

```powershell
powershell.exe -NoProfile -File scripts/Prepare-ScreenTranslate.ps1 -NoLaunch -DotnetPath ./.tools/dotnet/dotnet.exe
```

Без `-BuildOnly` скрипт после сборки проверяет отсутствие работающего приложения, Developer Mode, identity/version существующего пакета, выполняет регистрацию и проверяет фактические version/InstallLocation. `-NoLaunch` запрещает только автоматический запуск, **не регистрацию**. Без `-NoLaunch` успешная регистрация также запускает приложение; вручную его можно открыть через меню Пуск.

Это локальная development-регистрация, **не подписанный MSIX-инсталлятор**. Не перемещайте и не удаляйте зарегистрированный layout (включая прежний `artifacts/screen-translate` или каталог Lazy Dictionary). Старый пакет продолжает использовать прежнюю папку до отдельной успешной перерегистрации. При отказе preflight он не меняется; транзакционный rollback самой Windows-регистрации не обещается. После этапа build-only пакет **0.1.0.2** реально зарегистрирован и проверен; подробные границы проверки приведены ниже.

Совместимость сохранена: пакет `DevLn737.ScreenTranslate`, publisher `CN=LazyDictionaryDev`, AppId `Translator`, mutex/event и `%LOCALAPPDATA%/ScreenTranslate`. Историческое имя publisher намеренно не переименовано: это часть идентичности установленного пакета, а не зависимость от исходного репозитория.

## Использование

- **Home** — снимок монитора под курсором, выделение фразы мышью, OCR и перевод.
- **End** — свежий снимок прежней области. После перемещения/изменения размера окна нужно выделить её заново.
- **Insert** — другой перевод последнего распознанного текста через Google без нового снимка, в исходном окне.
- **Esc / правая кнопка мыши** — отмена выделения. Автоотмена через 30 секунд или при смене активного окна.
- Новый запрос отменяет предыдущий; устаревшие ответы не показываются.
- Карточки не забирают фокус, пропускают клики и исчезают автоматически. Длинный перевод разбивается на страницы.
- Трей: выделение, повтор, альтернативный перевод, копирование, пауза горячих клавиш, настройки, выход.
- Настройки: три сочетания клавиш, время показа, оригинал и тренировка. Некорректный файл настроек заменяется рабочими значениями в памяти.

Рекомендуется **оконный режим без рамки**. Эксклюзивный fullscreen, защищённый контент, elevated-приложения и ограничения античита не гарантируются. Нет внедрения в процессы, драйверов или обхода античита. При чёрном снимке используйте оконный режим. HDR не проверен.

## Данные и приватность

OCR выполняется локально. Во внешний сервис уходит только распознанный текст выбранной области — не снимок, координаты или заголовок окна. Основной сервис — Яндекс, альтернативный — Google; при ошибке весь текст повторяется через Bing. Части разных сервисов не смешиваются. Ответ Bing не кэшируется, чтобы временный отказ не закреплял резервный провайдер.

Снимки, тексты и FIFO-кэш до 128 записей хранятся в памяти. Основной и альтернативный перевод имеют отдельные ключи; попадание в кэш не меняет порядок вытеснения. Настройки — `%LOCALAPPDATA%/ScreenTranslate/settings.json`. Буфер обмена меняется только по команде пользователя. Нет фонового OCR, истории экранов или телеметрии.

`--diagnostics` пишет структурированные технические события в `diagnostics.txt`: максимум **64 KiB**, не более 256 байт на запись, с очисткой прежнего содержимого при достижении лимита. Распознанный текст, снимки, URL, пути, сообщения исключений и персональные данные не записываются; ожидаемые ошибки доступа/IO не прерывают основной сценарий.

`--self-test` использует сгенерированную фразу, выполняет реальный OCR и сетевой перевод, записывает `self-test.txt` и требует package identity. Коды завершения: **0** — успех, **1** — ошибка, **2** — экземпляр уже работает, тест **не выполнен**. При коде 2 настройки существующего экземпляра не активируются и старый `self-test.txt` не меняется; его PASS не подтверждает новый запуск. Обычный второй запуск активирует настройки. `--practice` открывает локальную тренировку.

## Структура и реализация

- `apps/windows/ScreenTranslate/` — приложение, манифесты и собственные Assets.
- `Capture/` — локальные горячие клавиши, `Capture/Ocr/` — захват, bitmap и Windows OCR. Это копии общих компонентов, адаптированные к namespace ScreenTranslate; source links в другой репозиторий отсутствуют.
- `App.xaml.cs` — shell: композиция, startup/shutdown, трей, горячие клавиши и создание окон.
- `RequestCoordinator`, `RequestSession` — жизненный цикл запроса capture → selection → OCR → translation → presentation, отмена, session-bound callbacks, repeat-anchor и результаты. Шлюзы удерживаются до фактического завершения неотменяемых операций.
- `WindowsRequestPlatform` — реальные Windows-адаптеры захвата/OCR, контекста окна, выделения и показа; зависимости координатора подменяются в тестах.
- `GameTranslator.cs` — последовательные провайдеры, отдельный FIFO-кэш основного/альтернативного перевода, отмена ожидания. Реальный сетевой вызов библиотеки не принимает CancellationToken: следующий запрос ждёт освобождения шлюза; HTTP timeout ограничивает ожидание.
- `CaptureAnchor.cs` — валидность сохранённой области относительно исходного окна и подключённых мониторов.
- `SelectionWindow`, `SelectionFrame`, `PassiveWindow` — выделение без активации окна, четыре тонкие границы и coalescing движений мыши.
- `TranslationPopup`, `PopupPagination`, `MonitorLayout` — shared measurement отображаемого WPF content, визуальные страницы и доступная область в DIP с учётом DPI. `TranslationPolicy` задаёт размещение/время чтения и отдельно provider chunks.
- `Preferences`, `SettingsSavePolicy`, `SettingsWindow` — проверка и сохранение настроек, общий save-путь для «Готово»/«Попробовать», обновление OCR status через Dispatcher без потери draft.
- `StartupPolicy`, `DiagnosticSink` — решение о втором запуске/self-test и ограниченная best-effort диагностика.
- `tests/ScreenTranslate.Tests/` — алгоритмы, координатор с fake dependencies, провайдеры без внешней сети, настройки и WPF offscreen/native проверки.
- `scripts/Prepare-ScreenTranslate.ps1`, `ScreenTranslate.Build.psm1` — publish в уникальный layout и отдельно guarded registration; `tests/scripts/` — безопасные mocked script tests.

GTranslate 2.3.1 подключён напрямую; уведомление о лицензии находится в `docs/third-party/` и копируется в сборку.

## Стабилизация и проверка — 11.11.2026

Перед исправлениями сохранён source snapshot в `.tools/audit-baseline/`. Контрольные Release-тесты **исходного snapshot на отдельной копии: 50/50** — отдельный baseline. Финальный изменённый solution: **127 passed / 0 failed / 0 skipped**, 13 секунд, локальный SDK 10.0.400, `test -c Release --no-restore`. Изолированные PowerShell regression tests: **30/30**, без реальных package/process/publish/launch операций. Независимые ревью A и B не выявили actionable P1/P2; все 9 проверенных SHA-256 совпали с review snapshot.

На предыдущем этапе исправленный `-BuildOnly` завершился с exit 0 и создал отдельный layout **0.1.0.1**, не затронув установку. Затем, с разрешения пользователя, исходный manifest повышен до **0.1.0.2** и новый уникальный layout зарегистрирован: Windows подтвердила Status=Ok, Version и InstallLocation. Скрипт не повышает версию автоматически и не разрешает перенос той же версии в новый путь. История и локальные отчёты — [VERIFICATION](docs/VERIFICATION.md).

Реализованный контракт UI/повтора (проверен в пределах автоматизированных тестов, не игровым прогоном):
- Карточки измеряются по доступным ширине/высоте и DPI. Если перевод и полный оригинал не помещаются вместе, сначала показываются страницы перевода, затем явно подписанные страницы «Оригинал»; первый фрагмент не подменяет полный исходник.
- Разовое ручное выделение может выходить за foreground-окно. Repeat-anchor сохраняется только для непустой области целиком внутри известных bounds исходного окна и доступного монитора; при потере контекста/геометрии повтор инвалидируется. Проверки bounds/foreground не обнаруживают любое перекрытие и не превращают desktop capture в захват содержимого одного окна.

После регистрации **0.1.0.2** повторно подтверждена неизменность SHA-256 всех **481 файлов** старого `artifacts/screen-translate` и пользовательского `settings.json`. Приложение до обновления уже было остановлено, принудительное завершение не применялось. Свежий packaged `--self-test` завершился с **exit 0 / PASS**: реальный Windows OCR сгенерированного изображения, перевод Яндекса и альтернативный ответ Bing. **Google не подтверждён:** сработал fallback, точная причина не сохранена текущей обработкой ошибок провайдеров. Это **не захват рабочего стола**.

Обычный второй packaged-запуск завершился с exit 0 и открыл настройки исходного процесса: проверены 7 UIA controls и снимок окна со статусом «Готово · английский → русский». Второй `--self-test` при работающем экземпляре дал **exit 2**, без активации настроек или изменения settings/отчёта; исходный процесс оставлен в трее. Результаты автоматических тестов выше относятся к предыдущему этапу, повторно здесь не запускались.

Покрытие не исчерпывает всю матрицу отказов: реальный захват через Home/End/Insert, длинные нативные popup, игровой и длительный прогон, HDR и mixed-DPI не проверены. Offscreen DPI tests не проверяют runtime `ShowPrepared` на mixed-DPI; fake Dispose не доказывает teardown реального WPF Dispatcher. Нет полного fault injection для Capture/OCR/Select/Present и полного покрытия alternative lifecycle. Успешные тесты и ревью не снимают этих ограничений.
