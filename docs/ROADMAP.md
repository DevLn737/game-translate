# Развитие Screen Translate

Предложения по результатам изучения реализации, 11.11.2026. Это план, а не обещание уже реализованных функций.

## Оценка текущей реализации

Для небольшого on-demand инструмента выбрана разумная схема: системный OCR, отсутствие внедрения в игру, программная отрисовка, ограниченные снимки и кэш, последовательная работа с сетью, неактивируемые окна. Выделение в отдельный проект убирает ненужные зависимости словаря без переписывания рабочего механизма.

Основной следующий риск — не количество функций, а подтверждение стабильности на реальном игровом окружении. Не установлен источник ранее сообщённого зависания Windows. Библиотека перевода использует неофициальные сетевые интерфейсы. В этапе стабилизации координация вынесена из App.xaml.cs в RequestCoordinator/RequestSession с WindowsRequestPlatform; App остаётся shell/composition. Автоматизированные проверки не заменяют реальный игровой прогон. Новые возможности нужно добавлять после надёжного базового сценария.

## P0 — стабильность перед релизом

1. **Ручная проверка захвата и фокуса.** Тренировка → обычное окно → игра без рамки. Проверить Home, End, Insert, Esc, быстрые повторные запросы, Alt+Tab, паузу, выход во время OCR/перевода. Измерять задержки и память, не записывая распознанный текст. При повторении зависания остановить игровое тестирование и разбирать системные события; не объявлять причиной WPF/GPU без доказательств.
2. **Матрица экранов.** 100/125/150/200% DPI, второй монитор слева/сверху, перемещение и resize окна, отключение монитора, HDR отдельно. Особенно проверить длинные карточки: разбиение по измеренным ширине/высоте WPF content уже реализовано в стабилизации, но offscreen DPI tests не подтверждают runtime-показ на реальной mixed-DPI конфигурации.
3. **Наблюдаемые ошибки провайдеров.** Различать timeout, отсутствие сети, ограничение частоты и невалидный ответ; короткий cooldown на недоступный сервис и ручной повтор. Не добавлять бесконечные фоновые retry. Сохранить инвариант: весь текст переводит один сервис, отменённые результаты не показываются.
4. **Надёжная доставка.** Подписанный MSIX, обновление/откат, тест установки на чистой Windows с отсутствующим English OCR. Переименование publisher требует отдельного плана миграции идентичности и данных.

Критерий выхода: воспроизводимая матрица сценариев, отсутствие необъяснённых падений/зависаний в согласованном тестовом прогоне, понятные ошибки и воспроизводимая установка. Объём реального прогона определяется окружением, не unit-тестами.

## P1 — полезные функции без постоянного захвата

| Функция | Зачем | Границы реализации |
|---|---|---|
| Профили игр | Свои клавиши, размер шрифта, длительность и язык для каждой игры | Явное создание профиля; область хранить относительно окна, инвалидировать при несовместимом resize/DPI; не отправлять имя процесса провайдеру |
| Выбор языков и движка | Не ограничиваться EN→RU | Проверка установленного OCR-языка, языки и провайдер в ключе кэша, миграция настроек; не просто добавление выпадающего списка |
| Глоссарий имён и терминов | Согласованные имена персонажей и игровых предметов | Локальный словарь, предпросмотр замен, границы слов и регистр; при официальном API использовать поддерживаемый glossary |
| Управление длинным переводом | Успеть дочитать без повторного сетевого запроса | Горячие клавиши «следующая/предыдущая страница», продление показа; не отбирать фокус у игры |
| Явная политика fallback | Пользователь контролирует, кому передаётся текст | Выбор разрешённых сервисов; возможность запретить передачу резервному провайдеру |

## P2 — только после подтверждения базовой стабильности

- **Режим субтитров по запросу пользователя:** фиксированная область, сравнение кадров/текста, ограниченная частота OCR, дедупликация, индикатор активности, немедленная пауза при смене окна. Не включать по умолчанию: это меняет текущую гарантию отсутствия непрерывного захвата.
- **Локальный перевод:** сменный backend, загрузка модели с явным размером и проверкой целостности, замеры RAM/VRAM и задержки параллельно игре. Не обещать качество и производительность до измерений.
- **История переводов — opt-in:** ограничение размера и срока хранения, удаление одним действием, понятное предупреждение о чувствительных текстах. По умолчанию сохранить режим без истории.
- **Официальные API провайдеров:** прозрачные лимиты/стоимость и надёжная авторизация; секреты хранить через Windows Credential Manager/DPAPI, не в settings.json или логах.

## Улучшение архитектуры по мере роста

- **Выполнено в стабилизации:** из App выделены RequestCoordinator/RequestSession для Capture → Select → OCR → Translate → Present и WindowsRequestPlatform. Внедряемые зависимости используются в тестах отмены, таймеров и контекста без реального рабочего стола; ограничения покрытия отмечены в [VERIFICATION](VERIFICATION.md).
- Провайдеры оформить единым интерфейсом с явными ошибками/таймаутами, когда появится второй тип интеграции помимо GTranslate. Сейчас не нужна универсальная плагинная система.
- Удалить неиспользуемые словарные OCR-модели при отдельном небольшом рефакторинге, опираясь на тесты; не возвращать source links между репозиториями.
- Ввести Windows CI: restore, Release tests, build-only package. Реальное игровое/OCR тестирование оставить отдельным проверяемым этапом, а не изображать его unit-тестом.

## Ручной чек-лист перед использованием новой сборки

- [ ] Закрыть старую версию через трей, зарегистрировать новый layout, запустить из меню Пуск.
- [ ] Проверить настройки и тренировочную фразу без игры.
- [ ] Выполнить packaged `--self-test`; проверить свежую дату файла и PASS, затем сценарий отсутствия сети.
- [ ] Проверить недоступность файла настроек: приложение остаётся доступным, ошибка сохранения понятна.
- [ ] Проверить повтор после перемещения/resize: требуется новое выделение, старое место не отправляется переводчику.
- [ ] Проверить смену приложения во время OCR и сети: нет устаревших карточек.
- [ ] Проверить масштабирование, второй монитор и длинный текст.
- [ ] Только после этого — короткий, затем длительный игровой прогон в режиме без рамки.
